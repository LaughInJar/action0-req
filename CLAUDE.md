# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`action0-req` is a Python library for representing, creating and manipulating HTTP requests and responses. It ships the `action0.req` package (`action0` is a PEP 420 namespace package) from a `src/` layout, is built with hatchling, and uses `uv` for environment/dependency management. Its only runtime dependency is `action0-url` (the URL representation, `>=0.2.0,<0.3` — capped below the next minor, since a 0.x minor may change behaviour: `Url` keeps its parts percent-encoded and round-trips a URL string as written), pulled from PyPI.

## Rules

- **Never commit without asking.** Also never push, tag, or publish on your own.
- **Branches + PRs.** All changes go through feature branches and GitHub pull requests that Simon reviews and merges — never commit to `main` directly. (Only the initial implementation was built directly on `main`; that phase is over.)
- **Discuss first.** Always present the plan and the intended edits and get agreement before changing files.
- Every code change comes with: tests, docstrings, inline comments where the code isn't self-explanatory, and updated usage examples in `README.md` and the Sphinx docs (`docs/usage.md`).
- Before considering work done, run ruff, mypy, and pytest (commands below) and fix what they report.
- Supported Python versions: 3.11 up to the latest release. Don't use syntax or stdlib features introduced after 3.11, and don't rely on behavior removed in newer versions.

## Commands

`uv run` syncs the environment automatically (the dev dependency group is installed by default), so no separate install step is needed.

```sh
uv run pytest                                    # all tests
uv run pytest tests/action0/req/test_init.py     # one file
uv run pytest tests/action0/req/test_init.py::PackageTestCase::test_version  # one test

uv run ruff check      # lint (add --fix to autofix)
uv run ruff format     # format
uv run mypy            # type-check (strict; files are configured in pyproject.toml)
uv run pyright         # type-check
uv run ty check        # type-check

uv run --group docs sphinx-build -W --keep-going -b html docs docs/_build/html  # build docs

uv build               # build sdist + wheel into dist/
```

`pytest` also runs the `>>>` examples in the docstrings as doctests (`--doctest-modules` over `src/`), so docstring examples must produce their shown output exactly.

## Architecture

The modules under `src/action0/req/`:

- `headers.py` — `Headers`: ordered, case-insensitive, multi-value aware mapping of header fields, internally a `list[tuple[str, str]]` of lines preserving the representation (order and casing) exactly. The `MutableMapping` view is single-value (last line per field, like `Params`); `get_all()`/`get_values()` (RFC 9110 comma-splitting)/`add()`/`set()`/`remove()`/`update()`/`as_lines()`/`as_dict()`/`as_str()` handle multiple lines. No underscore→dash normalization (header smuggling footgun). Names are compared by the private `_fold()`: ASCII letters lowercased, nothing else — deliberately not `casefold()`/`lower()`, which map lookalikes from outside ASCII (`Hoſt`, the Kelvin sign) onto ASCII letters. Lookups are answered from a lazily built index (`_fields()`: folded name → first-line name + values), dropped by every method that changes `_lines` — a class-level `_index = None` default keeps old pickles loading; `update()` merges in one pass and does not call `set()`. Every line goes in through the private `_lines()`, which refuses a CR, LF or NUL in a name or value, and a name that is empty or contains whitespace or a colon (`ValueError` — header injection/smuggling, `_check_name()`), a name that is not a str and a value that is not a str/int/float/bool, on its own or in a list (`TypeError` — bytes, `None`); the constructor raises a `TypeError` for what is no form of headers at all. `_check_safe()` (CR/LF/NUL) and `_check_token()` (additionally: not empty, no whitespace) are reused by `Request.as_str()`/`Response.as_str()` for the start line. A raw block is split at `\r\n`/`\n` only (never `str.splitlines()`), and a line with whitespace in its name is invalid. `get_values()` splits with the quote-aware `_split_elements()` (which also splits the `;` parameters of a Content-Type for `_charset()`). `__eq__` ignores field order and name casing but respects per-field line order, and is `False` (never raises) for a mapping that cannot be headers; `repr()`/`str()` redact the values of `Headers.secret_names` with `***` — only the wire rendering `as_str()` keeps them. `copy()` keeps the class and the instance dict (a `secret_names` set on the instance) without going through the constructor; requests and responses take headers over with the private `_own_headers()`, so a subclass survives. Also `Header`: `StrEnum` of the IANA HTTP field name registry (permanent + deprecated + provisional registrations, generated from the registry CSV, last compared on 2026-11-26) plus a block of unregistered de-facto `X-…` names.
- `status.py` — `Status`: custom `IntEnum` of the IANA status code registry with `phrase` and `is_informational`/`is_success`/`is_redirection`/`is_client_error`/`is_server_error` properties. Deliberately not `http.HTTPStatus`: the stdlib's code list and category properties vary across 3.11–3.15. Two pre-RFC-9110 aliases (`PAYLOAD_TOO_LARGE`, `UNPROCESSABLE_ENTITY`).
- `request.py` — `Method`: `StrEnum` of the RFC 9110 verbs + `PATCH` + `QUERY`. `Request`: `method` (a property uppercasing on every set, stored in `__dict__["method"]` so pickles from before it was a property still load), `url` (`action0.url.Url` — copied on ingestion by the constructor; a property like `method`: an assigned str is parsed, `None` gives an empty `Url`, a `Url` is taken as it is, anything else is a `TypeError`; `query=` kwarg replaces the URL's query like the `Url` constructor, except that `None` means "not given" and keeps it — deliberately, callers pass `query=None` for "no params"), `headers` (`Headers` — a property too: an assigned mapping/list/raw block/`None` is converted by the `Headers` constructor, a `Headers` instance is taken as it is), `body` (`bytes | str | BodyProducer | None`, stored as set; a `bytearray`/`memoryview` is a `TypeError` from every accessor — the private `_producer()`), `http_version`, `target` (explicit request target, `None` = derive the origin-form; for `*`, authority-form and absolute-form, which a URL cannot express; part of `copy()` and `__eq__`) and a `meta` dict (application metadata: never on the wire, excluded from `__eq__`, shallow-copied by `copy()`; the constructor copies the given mapping) as plain attributes. Typed body accessors `body_bytes()`/`body_str()`/`body_producer()` convert between the three forms using the Content-Type charset (default utf-8); `abody_bytes()`/`abody_str()` read a producer via `achunks()`. `close()`/`aclose()` + sync/async context manager as on `Response` (shared helpers in `body.py`). `copy(**overrides)` (own `Url`/`Headers`, same class; a `BodyProducer` body is shared; goes through the constructor and then takes over whatever else is in the instance dict — a `secret_params` set on the instance), part-wise `__eq__` (body compared as set), `repr()` redacts via `Url.__repr__` plus the values of the `secret_params` query parameters, also in a fragment written like a query (done on the rendered string by `_redact_query()` — setting a param on the Url would respell the query) and omits headers/body, `from_str(text, scheme=None)` parses what `as_str()` renders (URL from target + `Host`, no scheme assumed; a `Host` that is more than host[:port] and a second `Host` line are a `ValueError`; a target the Url would not reproduce is kept as `target`, so the text round-trips — but for the documented normalizations: the method is uppercased, and an absolute-form/authority-form request without `Host` is rendered with the derived one; body after the blank line as `str`), `as_str(include_body=False, separator="\r\n")` renders the wire format with origin-form target and derived `Host` (secrets included; a `BodyProducer` is never consumed — placeholder; bytes are decoded with `errors="replace"` and an unknown charset falls back to utf-8, a rendering never raises over the body; a method, target or version that is empty or contains a CR/LF/NUL or any other whitespace is a `ValueError`). Target and `Host` are cut out of the `Url`'s own rendering by the private `_request_target()`/`_host()`, never rebuilt from the decoded `url.path`/`url.authority`: the target is the URL's spelling character for character (escapes of a signed URL survive) — rendered behind a placeholder authority, so it is always an absolute path and gets none of the prefixes (`/.`, `./`) a URL without a host needs to round-trip — and the `Host` is IDNA-encoded.
- `body.py` — `BodyProducer`: runtime-checkable `Protocol` for streaming bodies: `content_length()` (`None` = unknown), sync `chunks()`, async `achunks()`, `as_bytes()`. Implementations: `BytesBody` (in-memory, single chunk; `__eq__`/`__hash__` by content; refuses a str), `FileBody` (path or open binary file object + `chunk_size`; paths open freshly per iteration → re-iterable, seekable file objects are rewound per iteration and never closed, non-seekable ones are single-use with unknown length; `content_length()` is `None` for a non-seekable file object and for a path that is not a regular file; `achunks()` does all file ops in a worker thread via the private `_in_thread` helper: the loop's default executor through `loop.run_in_executor` with a copied context — what `asyncio.to_thread` does, but a plain future and not a task, so cancelling all tasks of the loop cannot make the wait end while the function still runs —, or — when there is no running asyncio loop but `trio` is in `sys.modules` — `trio.to_thread.run_sync`; trio is never imported — it is a dev dependency for the tests only. Three dispatch variants: `_in_thread` never abandons a started call — on asyncio it waits for it through cancellations and re-raises afterwards (the result is lost then, so code opening a file in a thread records the handle itself); `_in_thread_shielded`, for cleanup (closing a file, the final flush), on trio also starts in a scope that is cancelled already; `_in_thread_abandonable` leaves the thread behind on cancellation — on asyncio a daemon thread (`_in_daemon_thread`, running the call in a copy of the caller's context like the pool does) instead of the loop's pool, taken from the private `_DaemonThreads` cache (an idle thread waits 10 s for the next call, so a pipe read chunk by chunk does not start a thread per chunk; a job returns its report function, which the thread calls only after it has put itself back — otherwise the woken consumer would find no idle thread), on trio `abandon_on_cancel` (`cancellable` before 0.23; the keyword is looked up once per `run_sync`, `_abandon_keyword()`) with the private no-op limiter `_UNLIMITED` — trio's default limiter keeps the place of an abandoned thread until it returns, and stalled reads would use it up. `FileBody.achunks()` uses it only for what may block for good: a path that is not a regular file (open and reads; the private `_OwnedFile` lets the abandoned call close the file) and a non-seekable file object. Regular files and seekable file objects are read with `_in_thread`, so a cancelled read never moves the position under the next reader. For `Response.body_file()` a `FileBody` hands out its seekable file via the private `_file_view()`: the given file object, or for the path of a regular file a newly opened file per call, tracked (under the module-level `_VIEWS_LOCK` — `abody_file()` calls it in worker threads, and a lock on the instance would cost the body its picklability) and closed by its public `close()`; `None` (→ spooled) for non-seekable/non-regular sources and for subclasses overriding `chunks()`/`achunks()`/`as_bytes()`), `IterableBody` (wraps `Iterable[bytes]`, unknown length; the single-use bookkeeping is the private base `_SingleUse`, shared with `AsyncIterableBody`; a source that is an `Iterator` is single-use: a second read, or a read after `close()`, raises a `RuntimeError` that explains it instead of yielding nothing, and a read that is under way when the body is closed raises at its end (`_cut`) — between two chunks when `close()` closes the generator, or inside the running generator when the callback takes away what it reads and it then returns as if done; a `close()` coming from the generator itself (`_called_from()` walks the frames) is its regular end; a generator that is running is not closed (`_close_generator()`, which also takes the race with a worker thread entering it for "running"); `threaded=True` makes `achunks()` fetch every chunk with `_in_thread_abandonable` and close in a worker thread, the default reads on the event loop; optional `close=` callback run exactly once — after consumption, on abandoned iteration or on `close()` — because a never-started generator's `finally` does not run; `close()` also closes a generator source — generators only, other iterables with a `close()` are left alone, and not a generator that is running right now: then the callback is what releases, and without one `close()` raises `RuntimeError`; `achunks()` closes the generator a re-iterable source made for the read, `_close_after_read()`), `AsyncIterableBody` (wraps `AsyncIterable[bytes]`, async-only: sync `chunks()`/`as_bytes()` raise `RuntimeError`; single-use like `IterableBody` for an `AsyncIterator` source; `aclose=` callback/`aclose()` as the async twin; `aclose()` also closes an async generator source unless another task is running in it (then as in `IterableBody`: callback and `_cut`, or `RuntimeError` without one); `achunks()` closes the async generator a re-iterable source made for the read; the sync `close()` is a no-op unless the callback is still pending or a started async generator — the source, or that of a read — is still open — then it raises `RuntimeError`), `SpooledBody` (written first, read afterwards: a `SpooledTemporaryFile` with its automatic rollover turned off — the class rolls over itself once `max_memory` is exceeded, so `awrite()` can stay inline while in memory and move the rollover and all later writes into a worker thread; the private `_Spool` subclass tracks the rollover, refuses one on a closed spool and closes itself when one fails — the stdlib has swapped the files by then, and a half-moved spool would hand out part of the data; every reader has a position of its own — `chunks()`/`achunks()` track an offset, `file()` returns a new read-only `io.BufferedReader` over the private `_SpoolView` per call (closing it leaves the body alone, no `fileno()`) — and a lock makes each seek+read/write on the one file object a single step, so overlapping readers are safe (`achunks()` reads inline only via the non-waiting `_read_inline`, never blocking the loop on the lock; a reader ends where the data ends — at `_size`, the end of the last complete write, not at the end of the file, where a failed write may have left a part —, so a body is to be read once complete); `close()`/`aclose()`/context managers remove the temp file). `close()`/`aclose()` are deliberately NOT part of the `BodyProducer` protocol (duck-typed by `Response.close()`), so third-party producers stay valid. `save_body()`/`asave_body()` copy a body into a path (`append=` for Range-resumed downloads) or file object — a path is opened only after the body's first chunk, so an unreadable body leaves the file untouched, and `_write_all` completes the short writes of a raw target (the remainder is passed as a `memoryview`; `None` from an `io.RawIOBase` is non-blocking "nothing written" → `BlockingIOError`; from any other file-like it counts as written); a generator of chunks is closed on the way out, so a failed write does not leave the stream half-read; the async one opens the file and writes the first chunk in one thread call, batches small chunks to 64 KiB per thread hop (the batch is taken over inside the thread, so a flush trio refuses to start loses nothing) and flushes what has arrived when the stream breaks off. Also the `BodyTypes` alias and the private helpers shared by `Request` and `Response`: conversion (`_charset`, `_body_bytes`/`_body_str`/`_body_producer`, the async `_abody_bytes`/`_abody_str` over `_read_all`, `_rendered_body`, which falls back to utf-8 for every charset Python cannot decode with; `_producer`, the `TypeError` for a `bytearray`/`memoryview` body) and closing (`_close_body`/`_aclose_body`, `_close_on_exit`/`_aclose_on_exit`) — the classes keep their own thin, documented accessor methods.
- `response.py` — `Response`: `status` (any int; `Status` members welcome; a property raising `TypeError` for anything else — a `bool` included —, stored in `__dict__["status"]` so old pickles load; rendered with `int()`, so a foreign int enum shows its number), `headers` (a converting property as on `Request`), `body`, `reason` (server-sent phrase; `None` = not known: the `phrase` property falls back to the `Status` registry, `""` for unknown codes; `""` = the server sent none), `http_version`, an optional `request` back-reference (metadata: shared, not copied, excluded from `__eq__`) and a `meta` dict like `Request`'s. Category properties (`is_success`, …) computed from the numeric range so unregistered codes work. Same body accessors as `Request` (sync and async), plus the response-only `body_file(max_memory=, dir=)` and its asynchronous twin `abody_file()` (reads via `achunks()`, spools with `awrite()`, awaits the replaced producer's `aclose()`; the `FileBody` lookup runs in a worker thread) (seekable file view; a streamed body is spooled and the `SpooledBody` REPLACES `body` so the response stays readable and closable; the replaced producer is closed. A producer with only `aclose()` is replaced by the private `_SpooledStream`, which carries that `aclose()` along. A `FileBody` is not copied and not replaced where it can hand out a seekable file itself (see `_file_view()`); otherwise it is spooled. A `SpooledBody` hands out a new read-only view per call), `save_body()`/`asave_body()` and `close()`/`aclose()` + sync/async context manager (release the body's connection or temp file; no-ops for in-memory bodies; `close()` raises `RuntimeError` for a body that only an awaited `aclose()` can release — the body's own `close()` raises it, or it has none; `__exit__`/`__aexit__` with an exception in flight attach any `Exception` from closing to it as a note instead of replacing it). Picklable with an in-memory body (pinned by a test — out-of-process caches rely on it). `copy(**overrides)` (same class; takes the rest of the instance dict along like `Request.copy()`), `as_str(include_body, separator)` with status line — the SP behind the status code stays also without a phrase (`"HTTP/1.1 599 "`, RFC 9112); an HTTP version that is empty or contains whitespace is a `ValueError` —, `from_str(text)` as its inverse (the phrase becomes `reason`, a missing one `""` — never `None`, which would make `as_str()` invent the registry phrase; documented normalizations: the SP behind the code is always written, the code as a number), redacting-by-omission `repr()` (`Response(404 Not Found)`).

Conventions:

- The version is single-sourced as `__version__` in `src/action0/req/__init__.py`; hatch extracts it with the regex in `[tool.hatch.version]`. Bump it only there.
- Releases: pushing a `vX.Y.Z` tag triggers `.github/workflows/release.yml`, which checks that the tag is on `main`, re-runs all checks, verifies the tag matches `__version__` and that `CHANGELOG.md` has a `## X.Y.Z — YYYY-MM-DD` section, builds, and publishes to PyPI via trusted publishing (environment `pypi`). Never bump the version, tag, or publish on your own — releasing is the user's call.
- Tests mirror the `src/` layout under `tests/action0/req/` and are `unittest.TestCase` classes, executed via pytest. `tests/test_docs.py` runs every Python block of `README.md` and `docs/usage.md` and compares what it prints with the block's `#` comments.
- Ruff enforces one import per line (isort `force-single-line`), line length 99, `action0` as first-party.
- Docs live in `docs/` (Sphinx + Furo, MyST Markdown pages, autodoc for the API reference). Docstrings are Sphinx-reST (`:param:`, `:py:meth:` roles). CI builds them with `-W` on every run and deploys to GitHub Pages on pushes to `main`; `nitpicky` is on, so a cross-reference without a target fails the build. Guide examples in `docs/usage.md` show exact outputs in `#` comments — `tests/test_docs.py` holds them to it.
